# 运营人员工作台设计

## 1. 设计目标

运营人员的首页不应该只是展示数据，而应该回答四个问题：

1. 今天必须处理哪些事情？
2. 哪些任务正在延误或存在风险？
3. 哪个基金公司项目需要关注？
4. 点击后能否直接完成下一步操作？

## 2. 首页信息架构

```text
运营工作台
├── 顶部上下文：当前客户/项目/时间范围/数据更新时间
├── 今日待办：待发布、待审核、待补充、即将截止、已过期
├── 任务健康度：草稿、已发布、进行中、已完成、异常
├── 客户项目概览：基金公司、基金产品、进度、完成率、审核积压、积分成本
├── 风险提醒：逾期、合规材料缺失、链接异常、名额不足
├── 任务列表：按优先级、状态、平台、客户筛选
└── 快捷动作：创建任务、发布、审核、补发、导出
```

## 3. 运营人员每日流程

```text
登录
→ 查看今日待办
→ 处理待审核提交
→ 检查即将截止任务
→ 发布或调整任务
→ 查看基金公司项目进度
→ 处理异常和补充材料
→ 汇总当日完成量与积分成本
```

## 4. 第三方基金公司边界

基金公司是客户角色，默认只读本公司项目数据：

- 查看任务进度和完成率
- 查看内容审核状态
- 查看投放平台和执行账号汇总
- 查看活动/产品对应的成本和效果
- 确认任务策略或补充活动资料
- 导出阶段性报告

基金公司不直接操作兼职人员审核、积分结算和内部组织权限。运营人员在客户项目概览中看到客户侧关键状态，但通过独立的客户视图完成客户协同。

## 5. 第一版优先级

### P0

- 今日待办队列
- 待审核提交列表
- 任务状态统计
- 任务详情中的下一步操作
- 基金公司项目概览

### P1

- 批量发布
- 审核超时提醒
- 链接回查结果
- 活动和权益过期提醒
- 客户确认记录

### P2

- 平台数据自动同步
- 账号质量分析
- ROI 和转化归因
- 自动补发和智能分配
